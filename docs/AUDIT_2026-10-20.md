## 1. 安全类问题

### A-01（P0，已修复）技能可绕过全局开关执行 Root 命令

- **位置**：旧 `agentpaw-core/.../skill/CustomSkillModel.kt` → `SHELL_COMMAND` 分支。
- **现象**：只判断 `phoneController is HybridPhoneController && phoneController.isRootAvailable`，没有读取任何全局开关。只要设备有 Root，任意用户技能（包括 AI 生成、从外部导入的技能）都能直接执行 `su -c` 命令，唯一门槛是技能级 `risk_confirmed:{name}`。
- **影响**：导入一条「技能」即可获得持久化的提权执行能力，且不经过资深设置。
- **修复**：新引擎增加**双层门禁**——技能定义必须声明 `guard.allowShell`，宿主还必须传入 `SkillRunOptions.allowShellSteps`（来自资深设置 `ALLOW_SHELL_SKILLS`，而它又依赖 ROOT 执行模式）。任一不满足直接 `FAILED`，确认对话框不会授予这个能力。
- **证据**：`SkillEngineTest.shell step is blocked unless the host enables it` / `shell step runs when enabled and confirmed`。

### A-02（P0，已修复）高风险技能「边跑边确认」，确认后整条重放

- **位置**：旧 `CustomSkillModel.execute` + `AgentTaskRunner.confirmAndExecuteRiskAction`。
- **现象**：技能执行到危险步骤才返回 `requires_confirmation`，Runner 随后用携带 `confirmed` 的同一工具名**从头重放整条技能**。前面的启动 App、点击、输入会全部再执行一遍。
- **影响**：对非幂等动作（发送消息、下单、删除）会造成重复副作用。
- **修复**：改为**执行前静态预检**（`SkillEngine.preflightRisk`）：扫描所有步骤的静态文本、DeepLink、shell，一旦命中风险，在第一步之前就要求确认；确认后从零开始执行，不存在“执行到一半再重放”。运行期新出现的风险（屏幕跳到支付页）改为 `SAFETY_PAUSED`，绝不自动续跑。
- **证据**：`SkillEngineTest.statically risky target requires confirmation before any step runs` 断言确认前 `steps` 为空且无点击发生。

### A-03（P1，已修复）明文 HTTP 策略与平台配置互相矛盾

- **位置**：`app/src/main/res/xml/network_security_config.xml` + `OpenAiCompatibleClient`。
- **现象**：XML 只对 `localhost / 127.0.0.1 / 10.0.2.2 / local` 放行 cleartext，但文档与错误提示宣称“本地内网 192.168.x.x 允许 HTTP 调试”。在真机上，`http://192.168.1.10:11434` 会被系统直接拒绝，用户看到的是 OkHttp 的 `Cleartext HTTP traffic not permitted`，与提示不符。
- **修复**：平台层改为放行（配置是编译期静态的，无法随开关变化），真正的闸门移到代码：新增 `NetworkPolicy`，默认拒绝一切 `http://`；资深设置分级开启（私网 / 公网）。关闭开关时下一次请求立即拒绝，不再是“配置写死”。
- **代价与说明**：任何绕过 `OpenAiCompatibleClient` 的新网络代码默认具备明文能力，因此 `NetworkPolicy.kt` 与 XML 都写明了「新增网络调用必须走策略判定」。
- **证据**：`NetworkPolicyTest`（5 项）。

### A-04（P1，未修复）敏感页关键词表过窄

- **位置**：`AndroidPhoneTools.kt` → `SafetyGuard.sensitiveKeywords`（10 条）。
- **现象**：包含「支付密码 / 输入密码 / 确认支付 / cvv」等，但缺「付款」「请输入密码」「Pay」「Amount」等常见文案；而 `RiskActionGuard.PAYMENT_REGEX` 覆盖更广。
- **影响**：英文界面、部分银行/钱包 App 的敏感页不会被 `SafetyGuard.isSensitive` 命中，截图与自动化仍会继续。
- **建议**：敏感页判定复用 `RiskActionGuard.PAYMENT_REGEX` + `DESTRUCTION_REGEX`，并抽出可配置词表。本轮未改，避免扩大改动面。

### A-05（P1，未修复）确认链路依赖 JSON 字符串匹配

- **位置**：`ToolControlSignal.parse`。
- **现象**：`status == "requires_confirmation"` 之外还依赖 `contains("\"requires_confirmation\"")`；只要工具结果文本里出现该字样（例如模型把上一条结果原样复述进参数）就会误触发确认卡片。
- **建议**：只认解析后的字段，去掉子串兜底；同时给 `ToolResult` 增加结构化控制信号字段。

### 5.3 「极高自由度」与「低门槛」如何同时成立

- **低门槛**：整条技能就是一段可读文本，`---` 之上写元信息、之下每行一个中文动作：
  ```
  名称: 微信搜索好友
  标识: skill_wechat_search
  参数: keyword | 文本 | 必填 | 搜索关键词 | 小明
  ---
  打开 微信
  点 搜索|Search
  输入 {{keyword}}
  回车
  ```
  编辑器提供 14 个动作的插入模板，不需要记语法。
- **高自由度**：同一份定义可切到「高级」模式编辑完整 JSON；另有结构化守卫面板（执行前确认、允许应用白名单、Root 命令、敏感页、总超时），以及每步可单独禁用。动作覆盖等待文本出现、滚动查找、界面快照、变量赋值、条件执行、失败重试/继续。
- **不丢草稿**：编辑器与许愿页共用导航图级 ViewModel，返回不重置。

### 5.4 许愿式生成

`SkillWishComposer.compose()` 的链路：

1. 提示词内嵌**完整动作目录**（每个动作的字段与风险等级），并要求只输出 JSON；
2. `extractJson` 容忍代码块、前后说明文字；
3. `JsonDoctor` 修复三类常见偏差：枚举大小写、数字写成字符串、布尔写成 `"是"/"true"`；
4. 用**与编辑器相同的** `SkillValidator` 判定；有错误则带诊断重问一次（只修不重写）；
5. 仍解析不出 JSON 时，退一步按速记格式解析，避免白等；
6. 结果先以预览呈现（步骤、参数、风险、诊断），用户点“保存并启用”才落库。

## 6. 资深设置中的高危开关

| 开关 | 默认 | 前置约束 | 生效点 |
|---|---|---|---|
| 允许 HTTP 传输 | 关 | 无 | `NetworkPolicy` → `OpenAiCompatibleClient` 逐请求判定 |
| 允许公网明文 HTTP | 关 | 必须已开启「允许 HTTP 传输」 | 同上（公网分支） |
| 允许技能执行 Root 命令 | 关 | 必须已开启「ROOT 执行模式」 | `SkillRunOptions.allowShellSteps` → 引擎硬门禁 |
| 允许在敏感页面继续 | 关 | 无 | `SkillRunOptions.allowSensitiveScreen` → 跳过安全暂停 |
| 临时跳过风险确认 | 关（最长 30 分钟） | 无，但到期自动失效 | `SkillRunOptions.bypassRiskConfirmation` |

约束实现位置：`HighRiskRules`（纯逻辑，可单测）+ `DataStoreSettingsRepository`（落盘）。UI 只是第二道防线：

- 每个开关开启前弹出**具体后果**说明，必须勾选「我已了解上述风险」才能点确认；
- 依赖未满足时开关直接禁用并说明原因；
- 关闭父开关会连带关闭子开关；关闭 ROOT 模式会连带关闭技能 shell；
- 读取时再做一次 `sanitize`，即使磁盘里存在脏数据，对外也只暴露安全值。
