# AIAPI 功能、体验修复与验证

## 用户可用功能

- 在「生成设置」选择思考强度：AUTO、NONE、MINIMAL、LOW、MEDIUM、HIGH、XHIGH、MAX。AUTO 不发送强度参数；具体可用值由端点和模型决定。
- 最大输出 Token 与最大总 Token 分开设置。总 Token 指**单次请求的输入与输出窗口预算**，不代表整项任务的累计费用或累计消耗。
- 总 Token 留空自动识别：优先使用连接测试获取的模型元数据；模型详情未提供时再尝试模型列表。随后尝试模型名中的窗口后缀和已知默认值，未知模型回退到 16000。界面区分「端点报告」和「当前估算」，均可手动覆盖。
- 自动压缩会预留系统提示词、工具定义及输出预算，并考虑中文文本和图片的估算开销。接近预算时主动压缩；服务端明确报告上下文超限后，尝试更强压缩并最多重试一次。关闭开关会同时关闭主动和被动压缩。
- 「综合测试」分别检查文字、流式、工具调用及图片识别，每项独立报告结果。最多发送四次小型请求，可能产生服务商费用；诊断工具只校验响应，不执行手机操作。

## 从用户视角发现并修复的问题

| 现象 | 修复 |
|---|---|
| 接口返回 HTTP 200 就显示连接成功，实际却不能生成 | 测试走正式调用链，校验有效文字回复；按照当前流式与思考配置请求 |
| 能聊天的模型不一定能读图或控制手机 | 新增独立的文字、流式、工具、图片综合测试 |
| 推理模型选择后报参数错误 | 识别常见推理模型，发送 `max_completion_tokens` 并省略采样参数；支持更多思考强度 |
| Token 输入无法清空，超大数字被悄悄当作自动模式 | 保留文本草稿；溢出和无效输入会阻止保存，不静默改值 |
| 长任务占满窗口后直接失败 | 主动预算压缩及一次被动恢复；无法容纳当前任务时给出明确调整建议 |
| 压缩可能丢掉最初目标，或拆开工具调用和结果 | 保留完整的最初目标、当前用户请求及最近工具交互；工具调用和结果作为整体处理 |
| 摘录历史被当作更高优先级系统指令 | 历史摘录以会话数据发送，不提升为系统指令 |
| 多工具调用中插入截图观察，导致接口拒绝历史 | 所有对应工具结果排在观察消息之前；中断的工具补充明确的缺失结果，不重放操作 |
| 历史中的工具内容只剩 UI 简写，模型得不到完整结果 | 优先使用脱敏后的完整工具日志 |
| 多张用户附件被截图保留数量限制误删 | 用户附件与截图分别管理，保留当前附件和最近截图 |
| 流式连接中断或输出达上限仍显示任务完成 | 缺少结束标记、输出截断和内容过滤会显示失败；不执行未完成的工具调用 |
| 流式结束后的独立 usage 片段被忽略 | 继续读取到终止事件，保留结束后到达的用量统计 |
| 无效或残缺的工具参数可能进入执行链 | 校验工具调用数量、标识、名称与 JSON 参数完整性 |
| 图片内容是 PNG，却以 JPEG 类型上传 | 持久化保留实际格式；上传编码通过文件签名识别类型，兼容旧的错误扩展名文件 |
| 长任务保留旧截图 Base64，多轮请求重复编码 | 释放旧截图引用，增加有界编码缓存和图片预览缓存 |
| 清理图片时异步写入又恢复图片，或内存仍保留缓存 | 串行化图片归一化和媒体清理；同步清空内存缓存，阻止清理前的解码结果重新入缓存 |
| 图片写入失败后附件消失 | 保留原始附件，避免静默丢失；采用临时文件与移动替换，清理失败不谎报成功 |
| 修改模型后，旧测试结果覆盖新配置 | 取消旧请求并清除旧结果；元数据与接口地址、模型关联 |
| 保存失败仍无反馈；恢复默认后部分参数没有恢复 | 展示保存错误；完整重置 LLM 参数，保留专家模式等非 LLM 偏好 |

参数适配参考：[OpenAI Chat Completions 官方接口文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。该接口使用 `max_completion_tokens` 约束包含推理消耗的输出，思考强度的可用值因模型而异。

执行核心模块和应用模块 JVM 单测、Debug APK 构建、Android Lint 与 `git diff --check`。测试覆盖配置边界、自动窗口识别及元数据回退、主动与被动压缩、协议顺序、综合能力测试、流式终止、工具参数完整性、保存异常、图片格式与清理并发。

## 明确边界

- 本地 Token 统计为估算，图片开销和不同模型分词器存在差异；端点报告不足时不能声称精确识别。
- 当前压缩使用本地摘录和旧工具输出缩减，不会额外请求模型生成语义摘要。最初目标和当前请求无法放入预算时会明确失败，要求增加窗口、降低输出预留或减少附件。
- 当前实现对接 Chat Completions 兼容协议。仅提供 Responses 或其他原生协议的模型需要兼容接口；并非所有模型都支持全部思考强度、图像或工具调用。
- 综合测试是针对当前配置的一次能力检查，不能保证复杂手机任务的执行成功率。
