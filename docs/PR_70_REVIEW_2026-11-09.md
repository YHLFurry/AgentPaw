## P1：系统指令没有转换为订阅路由支持的格式

位置：`app/src/main/java/com/paw/agent/chatgpt/ChatGptPlanClient.kt:118` 附近，`ResponsesCodec.request` 直接把 `m.role` 写入 input 项。AgentPaw 的正常任务上下文包含 `system` 消息，新增测试也构造了该消息，却只验证 JSON 生成，并未检查角色。

官方当前要求该路由使用 `instructions` 或 developer 消息，系统消息项会被拒绝。因此，单条 user 文本试通不能证明带系统上下文的正常任务可用。建议把 system 内容转换为 developer 消息或 instructions，并增加带系统指令、工具上下文的协议回归；用受控 HTTP 服务检查实际请求体。[OpenAI Docs：订阅路由限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## P1：工具定义仍使用不受支持的顶层平铺格式

位置：同文件 `ResponsesCodec.request` 的 `tools` 构造（125–129 行）。它直接写入顶层 `{type: "function", name, ...}` 数组。

当前官方要求函数/自定义工具放入 namespace，或通过 additional_tools 输入项提供。AgentPaw 的手机任务会携带工具表，这条路径需要适配，而不能仅验证无工具文字回复。建议采用受支持的 namespace 格式，同时验证返回的工具名映射、call_id 与结果回传。该结论来自协议文档与代码对照，未使用真实订阅账号重放。[OpenAI Docs：支持的工具格式](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

## P1：失效登录尝试仍能覆盖当前账号

位置：`ChatGptLoginActivity.kt:30–40`，以及 `ChatGptAuth.kt:89–106、132–136`。

登录任务在 appScope 中运行；“返回”只 finish Activity，不取消它。重新打开页面会创建新的按钮和第二次尝试。两个尝试各自保留旧凭证快照，回调只在最终写入时取得 mutex，没有检查尝试是否仍为当前尝试。首次登录 A 尚未完成时返回，重新登录 B 并完成，再完成 A，会再次写入旧尝试结果；旧页面也可能继续被 appScope 引用。

建议由单一会话管理器持有当前 attempt，启动新尝试、退出账号时取消旧 socket/job，并在写入前验证 attempt generation。配置变更只重新订阅状态，不重复发起授权。补充“回调乱序、返回重进、退出后迟到回调”测试。[Android 官方：ViewModel 生命周期](https://developer.android.com/topic/libraries/architecture/viewmodel)

## P2：固定超时及阻塞模型请求使取消不能及时生效

位置：`ChatGptPlanClient.kt:25、76–86`；`ChatGptAuth.kt:69–86`。

设置允许配置 10–300 秒超时，新传输却固定 readTimeout=180 秒、callTimeout=240 秒。模型列表和刷新令牌使用阻塞 execute，未注册取消时的 Call.cancel；切换服务或取消诊断只能取消上层协程，底层连接仍可能等到固定超时。complete 的流式调用已有取消处理，这两条路径需要同样覆盖。建议使用可取消的 suspend HTTP 封装，按配置派生客户端，并测试不返回数据的服务端下取消耗时。

## P2：退出账号丢弃客户端注册映射

位置：`ChatGptAuth.kt:65–67`。退出仅保留 host_id，client_id 和已验证账号映射全部丢弃；再次登录总走 dynamic_agent_client 注册，无法复用已有注册。当前官方要求退出后保留账号/client 映射与 host ID，并尝试结束可续期会话；网络撤销未确认时应明确告知用户。

建议分别保存非令牌注册信息与可清除凭证，在退出时停止请求、尝试撤销会话、清除令牌，随后重登复用原 client_id。现有“仅本机退出”提示已说明部分行为，但没有解决注册丢失。[OpenAI Docs：账号与会话](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)
