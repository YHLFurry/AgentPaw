# AgentPaw 自主审查与修复记录

日期：2026-10-26（Asia/Singapore）。本轮修改聚焦任务执行、断点恢复和授权操作的稳定性。

## 项目理解与检查范围

- `app`：Android 应用模块。`AgentPawApplication/AppContainer` 手动组织依赖；Compose + Navigation 提供聊天、历史对比、技能与设置页面，支持 Material/Miuix 主题。
- `agentpaw-core`：Android Library，包含可在 JVM 测试的 Kotlin 业务引擎，以及依赖 Android 的设备控制代码，并非整个模块都不依赖 Android。
- 执行链路：聊天输入 → `ChatViewModel` → 应用级 `AgentTaskRunner` → `Agent` 模型/工具循环 → `HybridPhoneController` → Root、Shizuku、无障碍通道。执行状态通过 StateFlow 同步给聊天与悬浮前台服务。
- 数据链路：配置使用 DataStore，凭据通过 Keystore 加密；会话使用 JSON 文件及历史索引，图片单独存入应用私有目录；技能使用版本化 JSON 存储。
- 构建基线：Kotlin 2.2.21、Gradle 8.13、AGP 8.13.2；compileSdk 37、targetSdk 36、minSdk 26。本轮使用本机 JDK 21。
- 已扫描 README、Gradle/CI 配置、两模块 Manifest、应用入口、导航与主要 ViewModel、数据仓库、网络客户端、Agent/技能/脚本引擎、设备控制与前台服务，并检索 TODO/FIXME/BUG/HACK/XXX。深入修复集中在任务调度与断点链路。
- 语音、工作流社区分享等规划项不具备本轮明确实现需求，保持现有功能边界。

## 根因与修复

| 问题 | 根因 | 修复与效果 |
|---|---|---|
| 停止后立即开始新任务，新任务被错误标为取消或空闲 | 旧协程的 catch/finally 直接访问共享 `activeAssistantId`、`isGenerating`，没有执行归属校验 | 为每次执行分配代次；旧任务事件、取消检查与清理只能影响所属执行。新任务的消息和运行状态得到隔离 |
| 空闲停止生成虚假断点，重复停止改写已有断点 | `stop()` 只防递归，没有检查任务是否仍在执行 | 停止入口增加运行状态检查，完成后停止无副作用，暂停后的再次停止保留原断点 |
| 已删除断点在重启后出现，运行标记丢失 | 断点保存、删除、运行标记写删分别启动 IO 协程，执行顺序不受调用顺序约束 | `TaskCheckpointStore` 单消费者顺序处理写删；使用临时文件和原子替换；沿用旧文件名和格式 |
| 冷启动读盘覆盖用户刚开始或刚放弃的任务 | 后台恢复直接修改运行状态，没有检查读盘期间的用户操作 | IO 读取与状态应用分离，恢复在调度器所属协程域内应用；检查持久化修订号，过期恢复结果被忽略 |
| 风险操作确认成功后，模型读不到真实返回值 | 手动新增的 TOOL 消息没有对应 ASSISTANT 工具调用，且调用 ID 不匹配；历史规范化会丢弃孤立结果 | 保存匹配的调用/结果对、脱敏完整日志和耗时；回归测试检查恢复请求中包含真实操作回执 |
| 新任务断点混入旧任务步骤，恢复后的再次暂停丢失完成清单 | 暂停扫描整个会话，且安全/风险断点没有携带已有完成步骤 | 按当前任务消息边界生成快照，保留结构化工具参数；恢复时继承已有步骤，安全/风险暂停也带上完成清单 |
| 断点时间戳可能在读回时改变 | 动态默认时间戳可能被默认序列化配置省略，反序列化时重新计算 | 断点存储启用 `encodeDefaults`，明确持久化时间戳 |

补充处理：损坏的断点 JSON 可回退到有效的运行标记；读取有大小限制；一次文件写入异常不会终止后续写入队列；无 Android Context 的内存使用场景不再共享系统临时目录下的断点文件。执行链路的非取消异常也会转换为失败状态。
